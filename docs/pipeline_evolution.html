Enhanced Pipeline — This Thesis
Voice Input
Raw spoken command
↓
Stage 1 Updated
Preprocessing
Trigger removal · medical abbreviation expansion (HD → hemodialysis) · urgency flag extraction (STAT, immediately) · non-speech format rejection
↓
Stage 2 New
LLM Structured Extraction
Filler word removal · synonym normalisation · extracts canonical {action, entity} JSON pair · handles informal phrasing ANTLR lexer cannot enumerate
↓
Stage 3 Updated
ANTLR Frame Validation
Validates LLM output against the real ANTLR4 grammar · command_type routing preserved · entity slot format enforced (set_medication requires INT + unit) · grammar is the single structural authority
↓
Stage 4 New
Ontology Lookup
Two-pass entity resolution: DOID (disease) · HP (symptom) · NCIt Thesaurus (procedure) · RxNorm (medication) · vital_signs. Global clarification search surfaces type mismatches.
↓
Stage 5 New
Semantic Type Validation
Checks resolved semantic_type ∈ action's allowed_slot_types · generates human-readable clarification ("Hemodialysis is a procedure, not a diagnosis")
↓
Stage 6 Pending
Intent JSON Output
Final structured payload for backend: action · canonical entity · semantic_type · urgency flag (from Stage 1) · clarification message if applicable
Evaluation — Stages 1–5 (243-command test set)
97.5% Binary accuracy
98.5% Valid recall
96.5% Invalid precision
Stage 3 note: In the enhanced pipeline, ANTLR no longer sees raw speech. The LLM normalises input to a canonical string ("ok glasses {action} {entity}") which ANTLR validates against grammar rules. The command_type hierarchy from Ludyga's grammar (GLASSES_COMMAND, REQUEST_DATA, PROTOCOL, SET_MEDICATION, REQUEST_PATIENT, MESSAGE, DIAGNOSIS) is fully preserved and used for backend routing.
