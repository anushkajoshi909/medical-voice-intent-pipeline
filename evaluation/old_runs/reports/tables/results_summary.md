# Results Summary

This file summarises the evaluation of the pipeline. It is generated by `evaluation/scripts/make_report_tables.py` from the run folders in `evaluation/runs/`. The thesis (Chapter 7) describes the evaluation in full.

## What was evaluated

The dataset has **243 commands**: 130 valid commands, which the system should accept, and 113 invalid commands, which it should not accept (ambiguous, meaningless, out of domain, or with an entity of the wrong type). Ludyga's grammar (**B0**) is the baseline. The pipeline of this thesis runs with four language models. DeepSeek V4.1 Flash and gpt-oss-120b run with 500 and with 4000 completion tokens, and Llama 3.3 and Gemma 4 with 500. Each system runs the dataset **three times** at the temperature 0.

The whole evaluation was made **twice** with the same dataset and settings: a **first run** and a **second run**. The second run confirms the decisions of the first, and it shows how much the response times depend on the load of the model service.

## How to read the tables

- **accuracy** is the share of the 243 commands that are decided correctly: a valid command that is accepted, or an invalid command that is rejected or sent to a clarification request.
- **valid accepted / valid → clarification / valid rejected** are the shares of the 130 valid commands with each outcome.
- **invalid wrongly accepted** is the share of the 113 invalid commands that the system accepts. Lower is better.
- **action accuracy** is the share of valid commands for which the language model finds the expected action. **model errors** are the share of calls without a usable answer.
- Values are percent, as mean ± standard deviation over the three repetitions. B0 runs once.

## In short

- **Baseline:** Ludyga's grammar reaches an accuracy of 70.8 % on the 243 commands (75.3 % on his own 198 sentences). It accepts only 46.2 % of the valid commands, because every wording that is not in the grammar is rejected, and it accepts 0.9 % of the invalid commands.
- **Pipeline:** the six systems reach an accuracy between 90.1 % and 95.9 % in the first run and between 90.2 % and 95.8 % in the second. The best is Gemma 4 26B in both runs (95.9 % and 95.8 %).
- **Cost of the flexibility:** the share of invalid commands that are wrongly accepted rises from 0.9 % to between 1.8 % and 7.1 % (first run). It is highest for Llama 3.3 70B (7.1 %).
- **Response time:** the median response time is between 0.37 s and 1.55 s in the first run and between 0.77 s and 1.54 s in the second. The fastest is Gemma 4 26B in both runs. The criterion of Ludyga is one second.
- **Both runs agree** in the decisions: the accuracy of every system differs by at most 1.1 points between the two runs. The response times differ more, because the model service is shared and its time depends on its load and on the network.

## Response time

The response time is the time from the text of the command to the structured result, in seconds. The call to the language model takes almost all of it. The models run on a remote service, so the times depend on its load and on the network. This is why the two runs differ.

| System | median, first run | median, second run | 95th percentile, first run | 95th percentile, second run |
|---|---|---|---|---|
| Llama 3.3 70B | 0.64 | 0.99 | 1.09 | 1.82 |
| Gemma 4 26B | 0.37 | 0.77 | 1.18 | 2.26 |
| gpt-oss-120b (500 tokens) | 1.55 | 1.51 | 5.90 | 5.31 |
| gpt-oss-120b (4000 tokens) | 1.13 | 1.54 | 6.13 | 5.63 |
| DeepSeek V4.1 Flash (500 tokens) | 1.26 | 1.04 | 3.82 | 2.62 |
| DeepSeek V4.1 Flash (4000 tokens) | 0.94 | 1.09 | 3.68 | 3.78 |

Reference: Ludyga's grammar needs 195 ms on average (Ludyga 2024, Section 7.3) and about 0.1 ms in our measurement. The criterion of Ludyga is at most one second.
